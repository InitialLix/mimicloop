# MimicLoop 内容生产与审核规范

- 规范版本：`1.2.0`
- 适用范围：Academic IELTS Writing Task 2 与辅助其写作训练的语言丰富度语料
- 第一批正文来源：IELTS 官方高分考生作答与 Cambridge 正版 model/sample answers

本规范把“范文交给 AI/Codex”变成可重复、可校验、必须经过人工审核的内容生产流程。固定的是质量门槛和字段契约，不是每篇文章的卡片数量。

## 1. 不可绕过的工作流

```text
完整原文或 URL
→ 保存 raw source
→ 生成 source metadata、段落索引和 SHA-256
→ AI/Codex 宽松提取候选句
→ 生成严格 JSON candidate
→ Schema 校验
→ 原文匹配、chunk/pattern/slot 一致性检查
→ 标准化文本与学习价值查重
→ 人工审核或编辑
→ approved seed
→ SQLite 正式库
```

AI/Codex 的输出永远从 `candidate` 开始。自动校验通过不等于内容正确，也不允许直接进入正式库。

## 2. 来源归档与可追溯性

每篇范文必须保存完整正文，不接受只保存零散好句。最低来源信息包括：

- 标题或 IELTS prompt；
- 完整原文与按原顺序生成的段落数组；
- `source_name`、`author`、`source_type`；
- `answer_origin`，明确区分官方评分考生作答、考官 model answer、教师范文或用户自写；
- 原始 URL，或书名、文件名和页码；
- 访问日期与 `sources/raw/` 下的本地文件路径；
- 基于未经学习化改写的正文计算的 SHA-256；
- 题型、主题、来源权利或访问说明；
- 只有来源明确声称时才填写 `claimed_band`。

第一批优先使用 IELTS 官方高分考生作答与 Cambridge 正版 model/sample answers。必须区分 `candidate_response` 与 `examiner_model_answer`：前者保留实际 band 和 examiner comments，后者保留书名、版本、测试编号和页码。Simon 等教师范文后续补充。网页无法访问时只保存 URL 与待办，不得由模型补写正文。

《新概念英语 3》、以后引入的外刊文章等非 IELTS 内容只作为 `language_richness_corpus`：用于发现自然书面表达、完整句子的框架、信息组织方式和可迁移写法，不作为 IELTS model essay，也不填写 IELTS prompt、题型、Band 或 examiner comments。文章来源必须按教材、刊物或出版方单列，不能混入 Simon、IELTS 官方或 Cambridge 来源。正式处理仍要求合法持有且保留原段落的 raw 文件、标题、作者或出版方、发布日期或访问日期、URL 与 hash；按段落扫描和定位，不根据网页句号列表猜测段落。详细决策见 ADR 0008。

处理 `language_richness_corpus` 时，筛选优先级固定为：先判断完整句子的框架、信息组织和自然写法是否值得迁移，再从所有段落高召回补充表达。不能因为短语更容易拆分和计数，就让大量零散表达淹没更有价值的整句写法；句子卡与表达仍分别查重、审核和训练。

语言丰富度语料的句子候选允许比 IELTS model essay 更充分。除直接适合议论文的论证句外，也可以收录能训练自然信息铺陈、强调、对比、限定、描述结果或组织长句的完整写法。准入依据仍是现代英语自然度、脱离上下文后的完整性、可解释的学习目标和真实迁移价值，而不是句长、文学感或“高级感”。

官方来源不等于句子自动合格。官方 candidate response 优先选择 Band 7.5 及以上材料，并逐句对照 examiner comments；考官明确批评的搭配、语法、衔接或论证问题不得作为正面学习卡。官方材料中 Band 7.0 以下作答默认仅用于错误对照。

正式卡必须通过 `source_essay_id + paragraph_index + sentence_index` 定位原句。`original_sentence` 必须能在对应段落中逐字匹配；若网页排版导致空格或标点差异，只能由确定性的标准化规则解释，不能静默修改原句。

## 3. 怎样判断句子值得收入

候选句至少满足以下一项，并且能明确说出学习目标：

1. 包含自然、准确、值得主动掌握的词块或搭配；
2. 包含可替换内容槽位的高复用逻辑或句法结构；
3. 清楚体现立场、解释、让步、比较、结果、解决方案等论证功能；
4. 能设计有效的词块填空、中译英回忆或槽位替换练习；
5. 对理解 IELTS body paragraph 如何推进论证有独立价值。

优先选择立场句、主题句、机制解释、让步/反驳、比较权衡、结果和解决方案。例句只有在它展示了可迁移表达或清晰论证动作时才优先收录。

## 4. 不应收入的句子

- 空泛开头和机械模板；
- 仅仅因为很长或看起来“高级”；
- 搭配可疑、语体不自然或考试时间内不实用；
- 离开大量上下文后指代不清、逻辑不完整；
- 学习价值与库内已有卡高度重复；
- 只有专有事实，没有可复用语言或论证价值；
- 为达到每篇数量目标而勉强加入。

## 5. 数量原则

每篇不设硬配额。AI/Codex 应高召回发现所有可能有价值的候选句，人工审核决定最终数量。语言丰富度高的教材课文或外刊文章可以明显超过以往每篇 5–10 句的经验范围；平淡、过度叙事、依赖上下文或与全库高度重复的文章也可以很少。不得因候选数量较多而删去真正有价值的完整句子，也不得为了体现“高召回”而降低质量门槛。

“至少 15 张正式卡”是开发种子整体的验收门槛，不是单篇配额。候选较多时可以标记优先级并由学习调度分散投放，不因担心一次学太多而删除好卡。

## 6. primary_focus 判断

### vocabulary

主要价值来自主题词块、固定搭配或自然用词。移除这些表达后，句法本身没有显著迁移价值。默认练习为完整 chunk 挖空、回忆以及目标词块简单造句；Use 不要求复杂结构。

### structure

主要价值来自逻辑关系和可替换句法。更换主题内容后结构仍自然有效，能够明确抽取 `pattern` 和 `slots`。默认练习为中译英回忆和经审核的槽位替换。

### mixed

词块与结构都构成主要学习价值。必须同时满足 vocabulary 与 structure 的要求，但仍要指定 `primary_focus: mixed`。Use 默认采用结构槽位替换，并提示尽量保留核心词块。

不能因为一句话同时有词汇和语法就默认标为 mixed；只有两类价值都值得独立训练时才使用。

## 7. chunks 选择标准

- 以完整、有意义的连续词块为单位，不随机选择单词；
- 优先固定搭配、常见语法搭配和承担论证功能的短语；
- 不因一个短语能翻译就把它标成 chunk；高中或基础四级难度、含义完全透明且没有搭配边界的表达默认不标注，例如 `encourage creativity`、`lack of exercise`、`could lead to`；
- 保留的 chunk 必须至少具备一项独立学习价值：非透明搭配、论证功能、容易误用的搭配边界或可直接用于有效练习；
- `text` 必须能在 `learning_sentence` 中精确找到；
- 一个 chunk 通常为 2–7 个英文词，确有必要时可以更长；
- 避免彼此重叠或把整句切成过多碎片；
- `meaning_zh` 简洁说明当前语境含义；
- `note` 只补充典型搭配、使用边界或常见错误，不写词典式长解释。

## 8. pattern 与 slots 抽取标准

pattern 保留原句的逻辑骨架和必要功能词，用 `{slot_name}` 替换可变化内容。slot 名使用小写 `snake_case`，表达语义角色而不是 `A/B/C`，例如 `{short_term_benefit}`。

每个 slot 必须：

- 在 pattern 中恰好承担清晰角色；
- 有中文角色说明；
- 保存原句中的 `original_value`；
- 至少有一个经审核的替换值；
- 替换后不破坏冠词、单复数、主谓一致或搭配。

structure 和 mixed 卡必须有 pattern、slots 和至少一道经审核的槽位替换题。vocabulary 卡可以不提供 pattern。

## 9. 轻量生词释义（glosses）

`glosses` 用于解释可能阻碍用户理解整句、但不一定值得作为核心 chunk 训练的单词或短语。它是阅读支架，不是把句子卡扩展成词典。

- 只标注确实可能影响理解的内容词或语境义，不标常见功能词；
- 已能从常见构词或当前上下文直接理解、且预计不会阻碍整句理解的高中/基础四级词汇不加 gloss；
- 普通句子通常标 1–4 个，没有必要时可以为空，不设机械数量配额；
- `text` 必须出现在 `learning_sentence` 中；
- `lemma` 保存基本词形，`part_of_speech` 保存当前句中的词性；
- `meaning_zh` 只写当前语境下最相关的简短中文义；
- `note` 只在直译易错、语体受限或存在常见混淆时填写；
- 不复制长篇词典定义，不罗列与当前句无关的全部义项；
- AI/Codex 生成的释义必须与其他候选字段一起进入人工审核。

chunk 与 gloss 可以指向同一文本，但只有当它既是核心训练目标、又确实需要释义时才这样做。UI 中 chunk 使用更明显的学习强调，gloss 使用更轻的标记。

## 10. 中文说明标准

- `translation_zh`：准确、自然，保留逻辑关系，不为了逐词对应而写生硬中文；
- `grammar_note`：只解释影响理解或复用的语法，通常不超过 120 个汉字；
- `usage_note`：指出搭配边界、语体、易错点或不适用场景，通常不超过 120 个汉字；
- `simplified_version`：在不改变核心立场和逻辑的情况下给出较容易的英文表达；
- `transfer_example`：仅在确有高迁移价值且例句经过审核时填写，不能伪装成原作者句子。

无法确认的内容写入候选卡 `uncertainties`，禁止用肯定语气掩盖不确定性。

## 11. 原句与学习句

`original_sentence` 永远保存来源中的原句。只有以下情况允许创建不同的 `learning_sentence`：

- 修复网页换行、不可见字符或明显排版噪声；
- 展开会阻碍独立学习的缩写，但不改变含义；
- 在有明确依据时补足极轻微的上下文指代。

不允许为了显得更高级而润色来源原句。任何差异必须写入 `learning_edits`，包含变更类型、变更前后文本和理由；无变更时使用空数组。

## 12. 练习种子

### Native-naturalness 强制门禁

生成仿写句时不得机械替换原句中的名词或主题。审核优先级固定为：

1. 现代英语中的自然度和地道度；
2. 语义逻辑准确；
3. 可用于 IELTS 或现代正式写作；
4. 最后才是尽可能保留原句结构。

原结构迁移后若显得生硬、老派、搭配异常或明显像套句型，必须缩小到真正可迁移的部分、改换更合适的主题，或不用该结构。不能为了保留所谓高级结构牺牲自然表达。

如果通过自然度审核的 Use 参考答案不再完整复用来源卡的 `pattern`，必须为该练习保存独立的 `feedback_pattern`。揭晓答案后展示的是本题真实使用的自然骨架；来源原句的原始 `pattern` 仍保留在学习卡中。禁止出现“参考答案已经改自然，反馈区却继续展示被淘汰旧模板”的情况。

每条 `transfer_example`、slot replacement、guided application 与 Collocation Use 参考答案都必须单独执行一次 blind native-naturalness check：假设审核者完全看不到原句，只判断该句是否像受教育的英语母语者在现代正式写作中会自然写出的句子。以下任一项存疑即不得批准：

- 名词与目标搭配只是语法上勉强成立，而不是典型组合；
- 单复数、可数性、冠词或介词选择不自然；
- 动词与宾语不是常见搭配；
- 存在明显更简单、更自然的常用表达，而当前写法只是为了复用复杂结构；
- 句子带有翻译腔、模板感、老派语感或脱离原句后难以独立成立；
- 语法正确但母语自然度不足。

Native-naturalness 属于人工语义门禁，Schema 与确定性检查不能替代。审核记录必须明确说明已经脱离原句独立检查，而不能只写“结构替换正确”。详细决策见 ADR 0009。

- vocabulary：至少一道按完整 chunk 挖空的题，答案必须与 chunk 完全一致；
- Use 的页面标题统一为“仿写练习”，具体目标只在目标结构或目标词块面板中出现；
- Use 不是开放造句：必须提供与参考答案语义对应的完整中文句子，较难产出的非考点词汇紧跟中文以 `中文（English）` 形式提示；
- `prompt_zh` 只保存中文正文，英文提示只保存于 `hints` 并由页面统一插入；禁止在题干中手写一次英文括注、同时又为同一中文配置 hint，否则会造成重复显示；
- 本卡要求掌握的核心结构或目标词块不得出现在括号提示中，也不得在作答前展示骨架；目标骨架和词块只能在显示参考答案后作为反馈出现；
- 中文提示、括号提示、目标词块和参考答案必须作为同一练习种子审核，参考答案不得与题意无关；
- vocabulary 的 `guided_application` 必须包含目标 chunk；参考答案必须原样使用该 chunk，不得只保留近似结构或换成另一词块；
- 运行时可以展示今日队列中最近完成的 structure/mixed 骨架作为可选支架，但必须明确允许用户不用；不得自动把两个不兼容的内容强行拼成参考答案；
- structure：至少一道槽位替换题，包含给定 slot 值、中文提示、必要词汇提示和参考答案；
- mixed：至少包含 chunk cloze 和 slot replacement；
- 中译英为参考答案 + 用户自评，不做自动同义判定；
- prompt 和答案作为快照保存，未来内容编辑不能改变历史尝试。

AI/Codex 补写的 Use 中文提示先进入 `data/use_prompt_candidates.json`，通过 `schemas/use-prompt-candidates.schema.json` 和确定性关联检查后仍保持 `candidate`。只有用户逐条或整批确认后，才可写回 approved card；未审核提示不得在正式学习流程展示。

## 13. 候选推荐与人工审核

每张候选卡必须写明：

- 为什么值得收录，具体学习价值是什么；
- vocabulary / structure / mixed 的判断依据；
- 潜在问题或不确定项；
- 原文匹配结果；
- 自然度、语境独立性、词汇价值、结构价值和迁移价值评分。

人工操作只有：`approved`、`needs_edit`、`deferred`、`rejected`。收录和编辑后收录必须写审核事件；驳回必须保存原因，避免模型下次重复推荐。

## 14. 自动校验门槛

进入人工审核前至少检查：

1. JSON 符合对应 Schema 且无未知字段；
2. `original_sentence` 与来源定位匹配；
3. chunk 和 gloss 存在于学习句，且 cloze 答案与 chunk 对应；
4. pattern 中的 placeholder 与 slots 一一对应；
5. structure/mixed 卡存在可执行的槽位替换种子；
6. ID、版本、时间、hash 和来源字段有效；
7. 标准化句子 hash 和学习价值查重通过；
8. candidate 状态没有绕过人工审核。

## 15. 版本与变更

- 所有结构化文件携带 `schema_version`；
- 候选卡记录 `guideline_version`、`prompt_version`、处理方式和模型标识（如适用）；
- 破坏兼容性的字段变化提升 schema major version，并提供 migration；
- 新增可选字段提升 minor version；修正文档或不改变数据含义的约束提升 patch version；
- Schema、TypeScript 类型、校验脚本、fixtures 和文档必须在同一变更中同步。

当前候选卡必须通过 `schemas/candidate-card.schema.json`，Use 提示候选必须通过 `schemas/use-prompt-candidates.schema.json`，正式卡必须通过 `schemas/sentence-card.schema.json`。
