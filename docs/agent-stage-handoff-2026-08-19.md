## 2. 当前产品已经具备什么

### 2.1 用户学习闭环

- 独立首页，并列进入“今日学习”和“原文库”；
- Sentence：Learn → Recall → Use → 次日 Review；
- Core Collocation：Learn → Recall → 换场景 Use → 次日 Review；
- Appreciation：只在原文中用暖色点状下划线标记，悬停、聚焦或点按显示简短释义，不进入强制学习；
- 今日任务默认加入 5 个新句子和 10 个新 Core，句子与 Core 的到期复习使用独立配额；
- 学习中断后可恢复，参考答案可展开和收起，所有尝试与进度保存在本地 SQLite。

### 2.2 语料库与阅读

- 句子、Collocation、完整原文三个入口；
- 中英文搜索、完整词形高亮、主题与来源筛选；
- 搜索或学习卡返回原文时，稳定定位目标句并短暂闪烁；
- 原文中的句子卡保持浅色荧光，Core 只加粗并可点击，Appreciation 使用点状下划线；
- 浏览器返回能够恢复进入文章前的筛选 URL，而不是总回到全部文章。

### 2.3 当前正式内容规模

| 内容 | 数量 | 说明 |
|---|---:|---|
| IELTS Task 2 范文 | 28 篇 | 当前均为 Simon 教师范文，不冒充 IELTS 官方评分样本 |
| 英语课文 | 12 篇 | 《新概念英语 3》第 18、27、29、38、41、44、45、47、51、53、55、59 课 |
| 正式句子卡 | 186 张 | 具有来源定位、中文提示、学习重点和 Use |
| Core Collocation | 286 条 | 全部进入 Recall → Use，并具有正式换场景应用题 |
| Appreciation | 115 条 | 只在原文中辅助欣赏和理解 |
| 全部表达 | 401 条 | Core 与 Appreciation 合计 |

《新概念英语 3》及未来可能加入的外刊统一视为 `language_richness_corpus`，不得展示为 IELTS model essay。处理时逐段高召回自然书面表达，同时重视完整句子的框架、信息组织与自然写法。

## 3. 已冻结的内容质量标准

所有正式内容继续遵循：

```text
raw source
→ metadata、访问日期、内容 hash
→ Codex 离线提取
→ Schema、确定性校验与全库查重
→ candidate
→ 人工审核或用户明确整批批准
→ approved seed
→ SQLite
```

仿写句和应用题的审核优先级固定为：

1. 现代英语中的自然度和地道度；
2. 语义逻辑准确；
3. 可用于 IELTS 或现代正式写作；
4. 最后才考虑保留来源结构。

每条参考答案必须脱离原句做一次 blind native-naturalness check。“语法正确但不够自然”、机械换名词、搭配勉强、翻译腔或套模板感都不能通过。Core 应真正具有主动迁移价值；修辞性强、较少主动使用但值得读懂的表达进入 Appreciation。

## 4. 技术与验证基线

- Next.js 16.3.1、React 19、TypeScript；
- `better-sqlite3` 本地数据库，migration、幂等 seed、版本化备份与恢复；
- JSON Schema 与确定性语义规则；
- 65 项规则单元测试、11 项数据库集成测试；
- `npm run typecheck` 与 `npm run build` 通过；
- 当前没有模型 SDK、运行时 LLM、账号、云同步或自动评分；
- 内部候选审核页面仍存在，但已经从普通用户主导航移除。

任何第二阶段实现都必须保留现有确定性学习闭环作为可运行的基线，不能让模型故障阻断原文阅读、Recall、Use、复习调度、备份或内容审核。

## 5. 已做过的智能体人工原型

`docs/guided-writing-agent-prototype-2026-08-19.md` 已用一道大城市住房题人工模拟完整流程：

```text
识别题目限定词
→ 选择立场
→ 先产生中文观点
→ 建立论证链
→ 按论证功能检索已学句子与 Core
→ 分层给提示
→ 组段
→ 完整成文
```

原型结论：现有产品已经有较强的“语言资产层”，但还缺少：

- 任务理解与题目限定词识别；
- 主题观点和事实边界；
- 因果、让步、权衡与段落逻辑；
- 学生已经掌握哪些表达的个体状态；
- 按“论证功能 × 主题 × 掌握度 × 自然度”检索和排序；
- 渐进提示与支架撤除状态；
- 对开放答案可靠、克制且可评测的反馈边界。

这意味着下一阶段不应只是给现有页面加一个聊天框，也不应先做整篇作文自动评分。

## 6. 尚未确认的工作假设

下面只是根据现有人工原型提出的一个讨论假设，不是用户已经确认的产品需求：可以考虑把第一版 Agent 定义为“引导写作教练”，而不是代写器或考官。

> 针对一道 Academic IELTS Writing Task 2 题，帮助用户完成审题、立场、论证链和一个主体段；在适当时机调用用户已学过的句子框架和 Core，并通过逐级提示让用户自己写出来。

如果用户认可这一方向，可以考虑先覆盖一个主体段，因为它已经能验证 Agent 是否真正会：

- 先教内容逻辑，再调用语言资产；
- 不为了复用高级句式而扭曲观点；
- 根据用户已学内容选择提示；
- 从中文意思逐步退让到关键词、表达名称、骨架和参考答案；
- 判断下一步是追问、提示、检索、纠错还是继续组段。

是否需要整篇作文生成、Band 分数、全文批改、自适应长期能力图谱、多 Agent 协作或自动扩充正式语料，目前全部未决定。新对话必须先听取用户目标，不能依据本交接文档自行排除或加入这些能力。

## 7. 目标确认后才可能采用的工程顺序

本节只解释在产品效果确认后，工程上通常还需要完成哪些工作；它不是新对话的首轮任务清单。具体阶段必须根据用户描述重新裁剪。

### Phase A：范围与评测先行

1. 明确 Agent 的单一教学任务、允许与禁止的输出；
2. 编写第二阶段 ADR，并同步修改 `AGENTS.md`、产品规范和实施计划；
3. 从现有 186 张句子卡和 286 条 Core 中建立可复现的检索测试集；
4. 准备 10～20 道 Task 2 题及人工标注的题目限定词、立场、论证链、可用语言资产和危险误用；
5. 定义评测指标：题意理解、逻辑有效性、资产检索相关性、自然度、提示泄露程度和教学动作是否合适。

### Phase B：确定性工具与离线导演

先设计并测试工具契约，例如：

```text
get_learner_state
search_learned_assets
get_source_context
save_writing_session
record_scaffold_level
```

用固定脚本或人工导演跑通状态机，确认数据库字段、刷新恢复、幂等和错误处理。此阶段可以没有运行时模型。

### Phase C：最小运行时模型

只有 Phase A、B 验收后才接入一个模型，让它在受控工具和有限状态机内决定下一教学动作。输出必须经过结构化 Schema 校验；模型不可直接写 approved 内容、学习进度或正式能力结论。

### Phase D：真实用户与对照

比较三条基线：固定流程、规则自适应、Agent。不要只展示“模型能聊天”，而要验证学生是否在新题目里更能主动调用学过的结构和 Core。
