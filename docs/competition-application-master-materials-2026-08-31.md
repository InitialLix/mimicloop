## 1. 产品事实快照

### 1.1 产品名称与定位

**MimicLoop** 由 Mimic（模仿）与 Loop（闭环）组成，是一款面向 IELTS Academic Writing Task 2 的表达学习与引导写作工具。

它要解决的不是“用户看不懂范文”，而是更常见也更难的问题：

> 学习者在范文中见过很多好句和搭配，但真正面对新题目时，仍然无法主动调取、自然迁移并组织成自己的文章。

产品以“真实语料 → 理解拆解 → 主动回忆 → 换场景应用 → AI 受控反馈 → 延迟复测 → 写作中迁移”为主线，把静态范文转化为可练习、可追踪、可迁移的语言资产。

### 1.2 当前内容规模

- 28 篇 Simon IELTS Writing Task 2 教师范文；
- 12 篇《新概念英语 3》课文，作为独立的语言丰富度语料，不冒充 IELTS model essay；
- 186 张经过筛选与审核的正式句子卡；
- 286 条 Core Collocation，均进入 Recall → Use 强制练习闭环；
- 115 条 Appreciation 表达，只在原文中辅助阅读和欣赏，不制造额外记忆负担；
- 28 道归档 Task 2 题目覆盖本地六类题型；另已实现学习者导入自己的新题并确认题型、主题后进入写作流程。

### 1.3 当前完成度

- 第一阶段本地单用户 Web MVP 已完成并冻结；
- 句子、Collocation、原文阅读、搜索定位、今日学习、复习调度和学习记录已经形成闭环；
- DeepSeek 已用于 Sentence Use、Collocation Use 的开放答案受控评价；
- Learning Agent 的 Phase 2.0–2.4 已完成；
- Guided Writing 已实现审题、论证链、两个主体段、Introduction、Conclusion、四段全文终检和自带 Task 2 新题入口；其中完整闭环与新题入口仍保留最终用户产品验收项；
- 不提供 Band 分数，不自动代写整篇作文，不把模型判断直接当作学习掌握事实。

## 2. 产品产生的真实问题背景

MimicLoop 并不是先想出一个“AI 教育”概念再寻找使用场景，而是从真实学习摩擦逐步长出来的。

传统范文学习常见四个断点：

1. **阅读和输出断开**：范文看懂了，但好表达没有被加工成能主动调用的学习单位；
2. **背诵和迁移断开**：能复述原句，不代表能换一个主题自然使用；
3. **单句和整篇断开**：积累了句子与搭配，却不知道在真实论证的哪个位置使用；
4. **AI 成品和学习者能力断开**：AI 可以快速给出漂亮范文，但成品质量只能证明模型会写，不能证明学习者会审题、构思、展开和表达。

因此产品逐步形成两个相互连接的层次：

```text
语言资产学习
原文 → 句子 / Collocation → Recall → Use → 复测

真实写作迁移
审题 → 立场 → 论证链 → 调用已审核语料 → 学习者写段落 → 受限反馈 → 四段闭环
```

这两个层次共同回答一个问题：**怎样把“见过的好英语”变成“学习者在陌生题目中真正写得出来的英语”。**

## 3. 核心用户与使用场景

### 3.1 目标用户

- 已具备基础英语阅读能力，但 IELTS Task 2 输出仍显得普通、翻译腔或模板化的学习者；
- 收藏过大量范文、词组和“高级句”，却缺少稳定复习和迁移练习的人；
- 希望获得具体写作过程指导，但不希望 AI 直接替自己写作文的人；
- 需要中文学习界面、明确学习目标和可追溯来源的中国学习者。

### 3.2 典型使用路径

1. 用户从首页进入“今日学习”或“原文阅读”；
2. 在完整范文/课文中阅读上下文，看到被标记的句子、Core 与 Appreciation 表达；
3. 点击进入句子卡或 Collocation 学习页，理解其学习价值、结构、搭配和来源；
4. 先 Recall，再完成不同话题或不同对象的 Use；
5. 可由 DeepSeek 检查表达是否准确、自然，并得到一个优先修改建议；
6. 用户查看参考答案并自评，系统保存真实尝试和复习状态；
7. 在 Guided Writing 中，把已经学过或经审核的新语料尝试迁移到自己的论证和段落中；
8. 最终仍由用户本人完成段落和四段文章，系统只做有边界的逻辑、语言与全文检查。

## 4. 当前功能全景

### 4.1 独立产品首页与六页使用导览

首页不是一打开就塞给用户一个大句子，而是并列呈现：

- 今日学习；
- 原文阅读；
- 写作练习。

六页动态使用导览用接近真实 UI 的局部动画依次展示：首页入口、原文标记、句子学习、Recall → Use → DeepSeek 批改、搜索定位和写作练习。导览支持暂停、重播、前后翻页和直接跳页。

### 4.2 完整原文阅读

- 显示题目、完整正文、来源和上下文；
- 已制作成学习卡的句子保留荧光标记，并注明 structure / vocabulary / mixed；
- Core Collocation 在原文中加粗，悬停可确认并点击进入学习；
- Appreciation 使用较轻的暖色点状下划线，悬停或点按只显示简短释义；
- 来源说明放在文章末尾，避免破坏阅读观感；
- 从搜索、句子卡或 Collocation 返回原文时，会定位并短暂闪烁目标句子。

### 4.3 句子学习卡

每张卡围绕一句话组织，而不是做成信息密集的通用 Dashboard：

- 英文句子左对齐，保持阅读感；
- 中文默认隐藏，可主动展开；
- 只标注真正有理解门槛的生词/词块，简单四级词汇不滥加注释；
- 点击释义后，点击浮层外也能关闭；
- 显示结构说明、使用提醒和可复用骨架；
- 保留作文题目、来源、上下文及回到完整原文的链接；
- `original_sentence` 与必要清理后的 `learning_sentence` 保持可追踪。

### 4.4 按目标分流的句子训练

不同句子并不做完全相同的练习：

- structure / mixed 句重点练论证关系、结构和槽位替换；
- vocabulary 句重点练目标词块，不强迫使用复杂句；
- Use 题首先给出一条完整中文句子；
- 核心考点本身不提示，非考点但较难的词才在括号中给英文；
- 参考答案在作答前隐藏，使用户答案和参考答案具有可比较的共同语义目标。

### 4.5 Collocation 独立学习系统

Collocation 不只是句子卡里顺便划出的词组，而是拥有自己的：

- canonical form、中文提示和多来源语境；
- 学习页、Recall、Use、进度和复习记录；
- pattern / slot / 常见错误等必要迁移教学；
- 与原文及关联句子卡的双向链接。

系统扫描的不只是“好句子卡”，而是完整原文中的所有句子。原因是普通句子也可能包含非常值得主动掌握的自然搭配。

### 4.6 Core / Appreciation 双层设计

语言丰富度语料采用高召回策略，不机械限制每篇只选三到五个表达：

- **Core**：中国学习者容易理解、但不容易主动写出的高迁移表达，进入 Recall → Use；
- **Appreciation**：自然、生动、有阅读价值，但不适合强制用于 IELTS 正式写作或不值得高频复习的表达，只在原文中标注和解释。

这一分层同时解决了“少收会漏掉语言价值”和“全收进复习会造成学习负担”两个冲突。

### 4.7 今日学习与复习

- 句子和 Collocation 组成带类型的统一队列；
- 每天保留新内容，同时加入到期复习，避免第二天只看到昨天的旧内容；
- 中途退出后可以从未完成阶段继续；
- 不使用“几分钟后复习”的页面停留计时，因为网页闲置不能证明用户实际学习；
- 以 Asia/Shanghai 自然日组织次日复习，并在今日任务结束后统一回看。

### 4.8 搜索与原文定位

- 支持中文和英文搜索；
- 结果中强调实际命中的词条；
- 英文词形强调会覆盖合理的复数等完整形态，避免只高亮 `job` 却漏掉 `jobs` 的 `s`；
- 范文可以按主题、来源筛选；
- 从任意搜索结果进入原文后自动定位并短暂闪烁，解决长文章中“虽然跳转了，但仍一眼找不到”的问题；
- 返回操作优先使用真实浏览历史，保留用户原来的搜索条件和滚动位置。

### 4.9 学习记录、Learner Model 与自适应下一步

系统区分：

- Recall；
- Guided Use；
- Transfer Use；
- Delayed Retention；
- Spontaneous Use（只有具备可信采集场景时才记录）。

学习状态由 append-only evidence 通过版本化确定性 reducer 重算，不让单次模型反馈直接改变“掌握”状态。自适应下一步也由有界规则选择，例如继续、回到来源、降低提示复测或跨主题练习，并保留旧队列作为安全回退。

### 4.10 DeepSeek 开放答案批改

Sentence Use 与 Collocation Use 都可以在答案揭晓前请求 DeepSeek 检查：

- 是否完成中文题意；
- 是否正确、自然地使用目标结构或搭配；
- 是否存在语法、搭配、词形、意义或明显笔误问题；
- 只指出一个最值得先改的问题，避免一次给出大段泛泛批改。

模型输出必须通过版本化 Schema 和本地语义校验。最终教学动作由确定性代码限制为：

- PASS；
- RETRY；
- GIVE_MINIMAL_HINT；
- SHOW_REFERENCE。

AI 关闭、超时、网络失败或输出无效时，用户答案仍被保留，并回到参考答案与自评流程。模型 verdict 不直接更新正式复习进度。

### 4.11 Guided Writing Learning Agent

写作模块的目标不是生成高分作文，而是让学习者保有思考与表达所有权：

1. 从服务端可信题目审题，识别任务要求和段落职责；
2. 由学习者先确定 Position；
3. 一次处理一个论证节点：Main point → Reason → Development → Takeaway；
4. Agent 只诊断当前节点，不供应观点，不直接写段落；
5. 从 approved 语料库为一个节点选择最多一个合适的 Sentence Frame / Rhetorical Move，以及零至三个 Core Collocation；不合适时宁可明确 NO CORPUS FIT；
6. 提示从 Level 0 到 Level 4 逐步展开，记录学习者实际看过的最高提示等级；
7. 四个节点通过后，由学习者本人 Paragraph Weaving；
8. Logic 与 Language 分开评价，每个维度最多指出一个优先问题；
9. 第二主体段、Introduction、Conclusion 仍由学习者本人写；
10. 全文页只拼接四段已保存原文，检查 Task Response、Coherence 与 Language，不生成改写稿和 Band 分数；
11. 学习者可以粘贴自己的 IELTS Task 2 新题，AI 只提出题型与主题判断，必须由学习者确认或修正后才进入正式写作上下文。

## 5. 内容来源策略与质量标准

### 5.1 来源优先级

项目确立的长期来源优先级是：

1. IELTS 官方公开的高分考生作答，并保留实际 Band 与 examiner comments；
2. Cambridge 正版材料中的 examiner-written model answer 或带评分评语的 candidate answer；
3. British Council / IDP 等官方合作方明确标注用途的样本；
4. Simon 等可靠教师作者的完整范文，作为补充和对照；
5. 来历不明的合集不得作为正式来源。

实际第一版经历过一个重要现实问题：IELTS 官方公开 sample response PDF 中包含手写考生答案，获取干净、可定位正文需要 OCR 和人工校对；Cambridge 正版内容还涉及合法持有和展示边界。为了先完成可用闭环，当前第一批 IELTS 文章使用了用户合法取得并本地归档的 Simon 28 篇合集，但产品明确说明其是教师范文，不宣称 IELTS 官方或 Band 9。官方/Cambridge 仍是后续内容升级方向。

### 5.2 IELTS 范文与语言丰富度语料分开

《新概念英语 3》以及以后可能加入的外刊不被当作 IELTS model essay。它们使用独立 `language_richness_corpus` 身份：

- 没有 IELTS prompt；
- 没有 claimed Band；
- 没有 examiner comments；
- 只用于提取可迁移句式、自然书面表达和 Collocation；
- 在索引中按真实出版物或来源单列。

这避免了为了增加内容数量而混淆“英语写得好”和“符合 IELTS 评分语境”两个概念。

### 5.3 固定内容生产工作流

```text
raw source
→ 来源 metadata、访问日期与内容 hash
→ Codex 离线高召回提取
→ JSON Schema 与确定性规则校验
→ 全库重复检测
→ candidate
→ 人工审核 / 修改 / 驳回
→ approved seed
→ SQLite 正式库
```

AI/Codex 生成的句子卡、Collocation、Use 题和迁移例句只能进入候选态，不能绕过审核直接写入正式训练内容。每条正式资产都必须能定位回原文。

### 5.4 不设固定收句配额

每篇文章不机械规定四到六句，也不规定每课三到五个搭配。是否收入取决于：

- 自然度；
- 独立完整性；
- 对中国学习者的主动输出价值；
- 跨话题迁移能力；
- 是否与现有库重复；
- 是否适合正式写作或只适合阅读欣赏。

不为凑数收句，也不因为超过预估数量而丢弃真正有价值的表达。

### 5.5 Native-naturalness 独立门禁

项目曾发现：机械替换原句中的名词和主题，可能得到“语法正确但母语者不会自然这样写”的句子。因此所有 Sentence Use、Collocation Use、`transfer_example` 和替换例句统一采用以下优先级：

1. 现代英语自然度和地道度；
2. 语义逻辑准确；
3. IELTS / 正式写作适用性；
4. 原结构保留程度。

每个新句必须接受一次脱离原句的 blind native-naturalness check：假设完全看不到来源，只判断它是否像受教育的英语母语者在现代正式写作中自然写出的句子。特别检查名词与搭配、可数性、单复数、介词、动词宾语、语体和模板感。语法正确但不自然仍不得批准。

## 6. IELTS 官方要求的产品转译

MimicLoop 对 IELTS 官方公开标准的使用方式不是“引用几个评分术语做宣传”，而是建立证据链：

```text
官方公开要求
→ 本地教学转译
→ 实际交互
→ 自动测试 / 模型基线 / 用户复检
→ 清楚说明尚未覆盖的边界
```

### 6.1 已进入产品的主要对齐点

- **Task Response**：检查是否完整回应题目、立场是否清楚、主要观点是否得到展开和支持；
- **Coherence and Cohesion**：通过 Main point、Reason、Development、Takeaway 检查逻辑推进，但明确这只是本地教学支架，不是 IELTS 官方规定的四句模板；
- **Lexical Resource / Grammatical Range and Accuracy**：在 Language 反馈中区分词汇搭配、自然度与语法，不把它们混成一句“表达不错”；
- **Introduction**：核对 Task framing 与 Thesis 是否与真实立场和两段正文一致，不强制华丽 Hook 或固定 `This essay will...`；
- **Conclusion**：检查是否收束题目、保持立场一致并避免加入新观点；
- **全文闭环**：按 Task Response、Coherence、Language 分开给出有限反馈；
- **至少 250 词**：由确定性代码计算。少于 250 词时，即使模型认为逻辑清楚，Task Response 仍稳定提示继续展开已有论证。

### 6.2 官方资料记录

项目当前登记的一手资料包括：

- IELTS Writing test preparation resources；
- IELTS Writing key assessment criteria；
- IELTS Writing Task 2 question prompt guidance；
- IELTS Academic Writing test format；
- IELTS Writing Task 2 Band Descriptors；
- IELTS / IDP introduction 与 position 指导；
- IELTS 官方 sample candidate responses 与 examiner comments；
- IELTS copyright and trade mark statement。

完整 URL 与产品证据状态登记在 `docs/ielts-official-alignment-register.md`。

### 6.3 对外表述边界

可以说：

- “产品设计参考并对齐 IELTS 官方公开评分维度”；
- “将官方评分关注点转化为本地学习步骤”；
- “使用官方公开资料校准审题和反馈边界”。

不能说：

- IELTS 官方认证、推荐或合作；
- 固定四句论证链是 IELTS 官方教学法；
- 系统可以准确预测 Band 分数；
- 使用后保证提分；
- 当前 Simon 范文是 IELTS 官方范文或官方 Band 9。

## 7. 技术架构与工作流程

### 7.1 技术栈

- Next.js 16 App Router；
- React 19；
- TypeScript；
- 服务端渲染的本地 Web 应用；
- SQLite + `better-sqlite3`，并保留 Drizzle migration；
- JSON Schema、Zod/本地语义校验；
- Vitest 单元测试与数据库集成测试；
- 浏览器关键路径与视觉验收；
- DeepSeek Chat provider adapter；
- 服务器端 feature flag、版本化 prompt/schema、超时与降级机制。

### 7.2 为什么不是“前端直接调用大模型”

开放答案评价采用受控服务端链路：

```text
浏览器只提交稳定 attempt / session 引用与学习者答案
→ 服务端从 SQLite 重建可信题目、目标资产和参考答案
→ 调用 DeepSeek
→ JSON Schema 校验
→ attempt ID、evidence span、置信度和语义一致性校验
→ 确定性 policy 选择有限教学动作
→ append-only evaluation / trace
→ 用户继续参考答案与自评流程
```

客户端传来的目标表达、题干或参考答案不被当作可信事实，避免篡改上下文或通过提示注入改变评分目标。

### 7.3 AI 与确定性代码的职责划分

**AI 负责：**

- 理解开放式答案；
- 判断语义、自然度、搭配与局部语言问题；
- 在受限候选中选择适合当前论证节点的语料；
- 提出一条有限、可操作的反馈。

**代码负责：**

- 正式内容身份与来源；
- Schema、权限和可信上下文；
- 尝试记录、幂等、事务和备份；
- 复习调度；
- 学习状态 reducer；
- 自适应下一步 policy；
- 250 词等可确定判断；
- AI 失败后的完整回退。

核心原则是：**LLM 可以理解和判断，但事实、规则和学习记账由代码拥有。**

### 7.4 数据与安全

- 正式学习记录保存在本地 SQLite；
- 内容 revision 更新不会覆盖既有学习进度；
- learning evidence、AI evaluation、guided-writing turn/draft/review 尽量 append-only；
- 重复提交通过稳定 ID 幂等处理，避免重复写入或重复推进进度；
- 数据库备份已随功能演进逐版升级并保持旧版本恢复兼容；
- API Key 只允许服务端从被 Git 忽略的 `.env.local` 读取，不进入浏览器、数据库、日志、trace 或 prompt；
- AI 默认可以关闭，关闭后核心学习闭环仍能运行。

## 8. 研发中最有挑战的问题及解决方式

### 8.1 把“好句”变成真正可练的内容

难点不在于让 AI 找出看起来高级的句子，而在于判断为什么值得学、练结构还是练词块、怎样设计新语境、怎样避免照抄和模板化。项目最终为句子建立 `primary_focus`，并让 Use 练习按 structure / vocabulary / mixed 分流。

### 8.2 大规模内容提取、查重和人工审核

28 篇范文与 12 篇课文中，句子、Collocation、原文位置、中文解释、迁移例句和练习题互相关联。一次处理两篇课文仍可能耗费较长时间，因为真正工作包含原文归档、段落索引、全库查重、候选分层、自然度检查、Schema 校验、人工审核和数据库发布，而不只是“一分钟读懂文章”。后来通过固定批处理脚本、候选审核台和可复用标准提高了后续速度。

### 8.3 防止 AI 生成“语法正确但不自然”的练习答案

早期仿写曾出现机械保留结构、错误搭配对象、重复中英提示等问题。解决方式不是增加更多模板，而是提高自然度优先级、建立 blind native-naturalness check，并允许放弃原结构或更换话题。

### 8.4 真实来源与版权/格式限制

IELTS 官方样本含手写答案，OCR 后仍需人工校对；Cambridge 内容有正版持有和公开展示边界；第三方合集来源质量不稳定。项目因此建立 raw source、metadata、访问日期、hash、来源类型和公开表述边界，并将当前 Simon 教师范文与未来官方/Cambridge 语料明确区分。

### 8.5 长文章中的精准双向定位

“有链接”并不等于“用户能找到”。项目经历过从句子卡返回失败、Collocation 能定位但句子不能、URL hash 到了但视线仍找不到等问题，最终统一建立稳定句子锚点、来源映射、自动滚动与短暂闪烁，并用真实浏览历史保留搜索筛选状态。

### 8.6 学习队列与跨日状态

真实使用中发现：第二天如果只重复昨天五句而没有新内容，学习体验会停滞；分钟级复习又无法区分网页闲置和真实学习。项目改为新内容与到期复习各有配额、队列可续接、次日自然日到期，并把复习提醒集中到今日总结。

### 8.7 开放答案没有唯一标准答案

参考答案无法覆盖所有自然表达，但直接让模型自由评分又容易误判。项目用 approved exercise、服务端可信上下文、gold set、Schema 与 evidence span 校验、有限动作和人工确认共同解决。合并 Sentence + Collocation evaluator 基线曾达到 49 条中 Schema-valid 100%、verdict agreement 95.92%、false pass/fail 0、blocking precision/recall 100%、fallback 0、duplicate write 0、p95 约 2.9 秒；该结果只证明受控基线，不外推为作文评分能力。

### 8.8 模型输出“看似合理但证据不存在”

DeepSeek 曾出现反馈内容基本合理、但引用的 evidence span 并非学习者原句真实片段的问题。系统不接受这种“意思对就算了”的输出，而是本地拒绝伪造 span，并只针对该格式错误自动补做一次模型请求；仍无效则安全降级。

### 8.9 让 Agent 帮助写作而不代替写作

这是第二阶段最核心的产品挑战。模型若直接给观点、句子和段落，页面会很快看起来“智能”，但学习者能力无法形成。项目因此把写作拆成可信审题、学习者先回答、单节点诊断、有限语料激活、逐级提示、学习者段落编织和分轴反馈，并保存答案来源与提示等级。

### 8.10 语料匹配不能只看主题词

早期检索可能因为都出现“动物”“人口”等主题词，就把逻辑角色不匹配的句式推荐给当前节点。后来将完整句型与局部 Collocation 分层选择，要求句型的论证功能和固定关系词也匹配；找不到时明确 NO CORPUS FIT，而不是硬凑一个“看起来相关”的高级句。

### 8.11 本地状态、刷新恢复和幂等

长写作流程包含多个 session、turn、argument node、语言尝试和四段草稿。刷新后跳回第一篇、上一节点提示串到下一节点、失败答案未恢复、重复请求推进两次等问题都可能破坏信任。项目通过 URL 状态、稳定 ID、append-only 表、事务、幂等冲突检查和逐版备份恢复解决。

### 8.12 UI 不是最后“美化一下”

产品迭代中大量关键问题来自真实使用：英文过大、中文过小且太浅、结构骨架像代码、弹窗只能点叉、搜索词少高亮复数、按钮灰掉、移动端换行、标签颜色和荧光冲突、返回丢失筛选状态等。这些问题直接影响学习者能否理解当前任务，因此 UI 与教学逻辑是一起迭代的，而不是最后套模板。

## 9. 人机协作方式与使用 AI 的亮点

### 9.1 不是“一句话生成一个产品”

整个项目采用持续对话、真实使用、发现问题、形成规则、编码、验证、再体验的循环。用户并没有被动接受 AI 的第一版，而是不断追问：

- 为什么一定要做这个功能？
- 这个页面到底想教什么？
- 练习目标与句子类型是否一致？
- 参考答案如果与用户输入毫无关系还有什么意义？
- 这个句子语法虽对，母语者真的会这样写吗？
- AI 给出的漂亮成品，究竟证明了谁会写？

这种质疑把 AI 从“答案机器”变成了可被审查的协作对象。

### 9.2 用户承担 Product Owner 与真实学习者双重角色

用户既提出产品方向，也持续以真实学习者身份点击和完成任务。许多重要决策都来自实际体验，而非预先假设，例如：

- 中文默认隐藏但入口必须明显；
- 简单词不应滥加注释；
- 不设每篇固定收句数量；
- 不用网页停留时间冒充学习时间；
- Collocation 必须换场景应用，而不只是背原短语；
- 原文、句子卡和搭配之间必须真正可定位；
- Core 与 Appreciation 要分层；
- 新概念英语更值得学习完整句式和自然写法，不应只拆搭配；
- Guided Writing 必须保持学习者自己的观点和句子。

这些反馈不是“改颜色”的零散意见，而是不断修正产品教学模型。

### 9.3 把聊天中的判断固化为工程资产

关键讨论没有只留在聊天记录里，而是逐步变成：

- 产品规格；
- ADR 决策记录；
- 内容审核规范；
- JSON Schema；
- 数据库 migration；
- 自动测试和 gold set；
- 官方依据登记；
- UX Reviewer 流程；
- 可恢复的候选审核与正式发布工作流。

这使 AI 协作不依赖“模型记得上次说过什么”，而依赖仓库中可复核的规则和证据。

### 9.4 AI 被分配到适合它的角色

项目中 AI/Codex 承担过多种角色，但每种角色边界不同：

- **研究与产品讨论伙伴**：帮助比较方案、暴露矛盾；
- **内容助理**：高召回提取候选句和 Collocation，但不能自行批准；
- **工程实现者**：把反馈落实为界面、数据与测试；
- **语言判断器**：通过 DeepSeek 评价开放答案和自然度；
- **写作教练**：一次诊断一个论证节点，不代写；
- **体验替身**：在需要用户重复点击验收时，用限制在 5 分钟、8 个动作内的 Rapid Trial Agent 发现明显问题；
- **记录员**：把新标准同步到文档、ADR、测试与实施计划。

### 9.5 “会限制 AI”是核心能力

项目最值得展示的 AI 素养不是调用了多少模型，而是清楚知道哪些事情不能交给模型直接决定：

- 正式语料是否批准；
- 来源身份和 Band 信息；
- 数据库事实与学习进度；
- 复习时间；
- 学习者是否真正掌握；
- 学习者的观点、段落和整篇作文；
- 最终 IELTS Band 分数。

模型可以提出观察，系统必须通过规则、证据和用户动作再决定后续。

### 9.6 从 AI 的失败反向形成产品标准

许多重要规则正是从 AI 的典型失败中产生的：

- 机械换主题 → native-naturalness gate；
- 硬凑相关语料 → NO CORPUS FIT；
- 伪造 evidence span → 本地语义校验与一次格式重试；
- 给太多建议 → 每轴最多一个优先问题；
- 直接给答案 → minimum-help scaffold；
- 模型判断冒充掌握 → append-only evidence + deterministic reducer；
- 新题分类可能错 → learner 必须确认或修正。

这形成了比“接一个聊天机器人”更成熟的人机协作范式。

## 10. 创新点与相对优势素材

### 10.1 从“收藏内容”转向“验证迁移”

很多工具停留在范文、词组、闪卡或 AI 批改。MimicLoop 把来源阅读、句子拆解、搭配学习、Recall、Use、延迟复测和真实写作串成同一条可追踪链路，重点不是用户看过多少，而是能否在新语境主动调用。

### 10.2 句子与 Collocation 双粒度学习

完整句式适合学习论证结构与自然写法，Collocation 适合局部、灵活迁移。两者进度独立，又都能回到同一真实原文，避免“只背大模板”或“只背碎片词组”的单一化。

### 10.3 Core / Appreciation 解决内容价值与认知负担的冲突

高召回保留语言丰富度，但只有 Core 进入强制练习；Appreciation 只服务阅读。这比简单地“多选一点”或“每篇固定五个”更符合真实学习价值。

### 10.4 按学习目标生成不同 Use

结构类练论证骨架，词汇类练自然搭配，混合类兼顾主次目标；中文提示隐藏核心考点、只提示非考点难词。练习形式由“为什么收这句话”决定，而不是所有内容套同一种题型。

### 10.5 受控 AI，而不是无边界 AI

DeepSeek 处理开放答案与语言理解，确定性代码维护事实、动作、进度和回退。模型输出被 Schema、可信上下文、语义校验、gold set 和有限动作共同约束，既接受自然变体，又避免自由聊天式反馈的不稳定。

### 10.6 学习者所有权优先的 Guided Writing

Agent 不以生成高质量作文为成功，而以学习者能否自己完成审题、论证节点、段落和全文为目标。提示逐级增加、实际使用语料和提示等级可追踪，最终成文始终来自学习者已保存的四段原文。

### 10.7 内容工程与产品工程一体化

产品不仅有页面，还建立了来源归档、hash、候选审核、全库查重、自然度门禁、版本发布和学习进度保护。正式内容的可信度与软件状态同样被工程化管理。

### 10.8 从官方标准到可操作步骤的证据链

产品不把 Band Descriptors 当宣传标签，而是记录官方要求、教学转译、实际 UI、验证证据和表述边界，能向评委解释每一步为什么存在，也能坦诚哪些效果尚未证明。

## 12. 当前局限与比赛前风险

1. 当前 IELTS 范文仍主要来自 Simon，官方/Cambridge 高可信来源尚未正式扩库；
2. 尚无大规模真实学习者的前测、后测和延迟迁移效果数据；
3. 单用户本地 SQLite 架构没有账号隔离，多人访问同一实例会共享进度；
4. `/candidates` 等内部维护页面在公开体验前需要隐藏或保护；
5. Simon 与教材原文的公开展示范围需要在正式公开部署前再次核对；
6. 手机端已有响应式处理，但全站窄屏、键盘和无障碍仍需比赛前专项验收；
7. DeepSeek 依赖网络、延迟和服务可用性，因此必须准备 AI 关闭时的确定性演示路径；
8. Guided Writing 2.5G–2.5H 已实现并验证，但仍保留最终产品验收项；
9. 不应在比赛前临时加入 Band 评分、多 Agent、全文代写或无审核自动扩库，避免破坏当前可信边界。

## 13. 比赛展示可以采用的故事线

### 13.1 推荐主线：一个表达如何从原文变成自己的能力

1. 在原文中展示一个 Structure Sentence 和一个 Core Collocation；
2. 点击进入卡片，展示来源、中文、结构和轻量释义；
3. 完成 Recall；
4. 完成不同语境的 Use；
5. 展示 DeepSeek 接受自然变体或指出一个具体问题；
6. 打开学习记录，说明“模型反馈不等于掌握，系统只记录真实证据”；
7. 进入 Guided Writing，在学习者自己的论证节点中调用已审核语料；
8. 展示学习者写出的段落和受限反馈，而不是展示 AI 生成作文。

这条线能同时表现内容、教学、AI、数据和产品闭环，优于逐页介绍所有功能。

### 13.2 推荐强调的三个判断

- **问题判断**：真正困难的不是找到好句，而是迁移；
- **AI 判断**：AI 应理解语言，但不能拥有学习事实和学生作文；
- **工程判断**：高质量语言学习产品既需要模型，也需要来源、审核、规则、状态和回退。

### 13.3 不建议的展示方式

- 不用“输入一个题目，AI 立刻生成高分作文”作为高潮；
- 不堆技术名词而不展示学习结果；
- 不展示大量卡片数量却不解释为什么值得学；
- 不把模型输出截图当成全部技术证据；
- 不声称 IELTS 官方认证或提分保证。

## 14. 三个报名栏目各自应该取什么素材

### 14.1 产品介绍（500 字以内）

建议保留：

1. 真实痛点：“看得懂、写不出”；
2. 产品定位：IELTS Task 2 表达迁移与引导写作；
3. 主闭环：原文 → 句子/搭配 → Recall → Use → AI 反馈 → 写作迁移；
4. 当前内容规模；
5. Guided Writing 坚持学习者自主完成；
6. 一句边界：不是作文代写或 Band 预测工具。

不建议在 500 字里展开：具体技术栈、全部测试数字、过多来源争议。

### 14.2 技术与应用（300 字以内）

建议保留：

1. Next.js / React / TypeScript / SQLite；
2. DeepSeek 受控接入；
3. 服务端可信上下文 + Schema + 语义校验 + 确定性 policy；
4. raw → candidate → human review → approved 内容管线；
5. append-only evidence、幂等、备份与 fallback；
6. 一个最代表性的难题，例如“开放答案无唯一标准答案”或“AI 判断不能直接等于学习进度”。

不建议把 300 字写成框架名单，应强调技术为何这样设计。

### 14.3 创新与优势（300 字以内）

建议聚焦三点：
