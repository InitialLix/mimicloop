# MimicLoop 最新产品介绍与功能说明

- 版本状态：第一阶段本地 Web MVP 已完成并冻结
- 更新时间：2026-08-19
- 当前范围：中文界面、个人自用、桌面优先、Academic IELTS Writing Task 2

## 1. 一句话定位

MimicLoop 是一款把 IELTS Task 2 范文中的高价值句子和 Collocation，通过“理解 → 回忆 → 仿写 → 换场景应用”练成主动表达的学习工具。

它不是作文批改器，也不只是范文阅读器或单词卡软件。核心目标是解决“看得懂范文，但写作时调不出来”的问题。

## 2. 当前产品形态

产品打开后先进入独立首页，不会直接把用户扔进某一个英文句子。首页提供两个并列主入口：

1. **今日学习**：完成新句、到期复习、Collocation 回忆和应用训练；
2. **完整范文库**：阅读作文题目和全文，并从原文进入对应句子卡或 Collocation。

首页另有一个主动打开的六页“使用导览”，依次说明：三个主要入口、原文中的句子/Core/Appreciation 标记、句子学习卡、Recall → Use 与 DeepSeek 反馈、句子与搭配的中英文搜索及原文闪烁定位，以及写作练习。每页均采用真实 UI 片段动画，支持暂停、重播、上一页/下一页、直接点页码和键盘方向键；第 4 页演示真实的受控 Use Evaluator 边界，不将反馈冒充 Band 评分或学习进度；第 6 页只概览“选择题库题目或导入自己的 IELTS Task 2 题目后进入写作练习”，不在导览中复述复杂流程。首次访问自动展示与“已看过”状态仍明确延期。

当前内容规模：

- 28 篇完整 Task 2 范文；
- 12 篇《新概念英语 3》语言丰富度原文；
- 186 张正式句子卡；
- 286 条 Core Collocation，均具有经过审核的换场景 Use 应用题；
- 115 条 Appreciation 表达，只在原文标注，不进入强制学习；
- 当前范文全部来自已本地归档的 Simon 范文合集，产品明确标注其不是 IELTS 官方范文或官方 Band 9。

《新概念英语 3》已作为独立的 `language_richness_corpus` 入库，只用于补充可迁移句式、自然写法与表达，不计入上述 28 篇 IELTS Task 2 范文。当前已归档并处理第 18、27、29、38、41、44、45、47、51、53、55、59 课。提取不设每课固定配额，先逐段高召回，再分为 Core 与 Appreciation；完整句子的框架和自然写法仍优先于机械拆词，句子卡也允许比 IELTS 范文收录得更充分。以后加入的外刊等材料沿用同一 `language_richness_corpus` 标准，并按刊物或出版方单列文章来源。

## 3. 今日学习系统

今日任务把“句子”和“Collocation”作为两种不同任务，使用带类型的统一队列交替排列，但每个页面始终只保留一个主要学习动作。

当前默认配额：

- 每天最多 5 个新句子；
- 每天最多 5 个到期句子复习；
- 每天固定加入 10 个新 Collocation；
- 最多再加入 10 个到期 Collocation，且不挤占 10 个新 Collocation；
- 当天中途退出后，再次进入会回到尚未完成的阶段，而不是从第一项重新开始。

所有任务完成后进入今日总结，统一回看当天学习内容。系统不使用“几分钟后复习”的页面停留计时；完成后的内容在下一个 Asia/Shanghai 自然日到期。

## 4. 句子学习闭环

### 4.1 学习卡

每张句子卡以一句英文为主视觉，并提供：

- 默认隐藏、可手动显示的中文释义；
- 少量真正有理解门槛的词块或生词高亮；
- 点击高亮后的简短中文解释，点击浮层外部即可关闭；
- 结构说明、使用提醒和可复用骨架；
- 作文题目、来源、上下文和回到完整范文原句的链接；
- 原句与清理后的学习句之间可追踪的修改记录。

### 4.2 Recall

用户根据中文提示写出原英文句子，随后可显示或收起参考答案并进行自评。Recall 只记录“能否回忆”，不会直接把该句判定为完成。

### 4.3 Use

完成 Recall 后必须进入 Use：

- structure / mixed 句重点练结构、论证逻辑和槽位替换；
- vocabulary 句重点练目标词块；
- 作答前显示一条完整中文句子；
- 只有较难且不是核心考点的词汇会以英文括号提示；
- 目标结构、目标词块和参考答案在作答前保持隐藏；
- 完成 Use 并自评后，才安排下一次复习。

## 5. Collocation 学习闭环

Core Collocation 是独立学习对象，同时保留与原句和范文的关系；Appreciation 是阅读层表达，不进入学习闭环。

### 5.1 详情学习

每条 Collocation 提供：

- 英文 canonical form 与中文提示；
- 必要时展示可迁移 pattern、slot 变化、语法提醒和常见错误；
- 一个或多个真实范文语境；
- 回到原文原句或关联句子卡的链接；
- 独立于句子卡的学习进度。

### 5.2 Recall

用户根据中文写出英文 Collocation。系统进行确定性匹配，只忽略大小写、首尾空格、连续空格和句末标点；不会把近义但不同的表达自动判成正确。

### 5.3 Use

Recall 之后必须完成一条不同对象或不同话题的中译英应用题：

- 中文提示是完整、具体的句子；
- 不提前显示目标 Collocation；
- 必要的非考点难词可以提示；
- 显示答案后才揭示本题调用的搭配及迁移类型；
- 完成 Use 后才更新 `application_score`、学习阶段和下一次复习日期。

当前 286 条 Core 已全部具备正式 Use 题；115 条 Appreciation 不生成进度或练习。Core 中一部分复用既有句子卡中经过审核的迁移语境，其余使用新写并经审核的应用题。

## 6. 语料库与范文阅读

语料库包含三个并列部分：句子、Collocation 和完整范文。

### 6.1 搜索与筛选

- 支持中文和英文搜索；
- 搜索结果会在句子或释义中强调命中的完整词形，包括合理的复数形式；
- 可按主题、来源及学习状态等条件浏览内容；
- 范文索引支持按主题和来源区分，为以后加入 IELTS 官方、Cambridge 或其他作者保留空间。

### 6.2 完整范文阅读

- 展示原始作文题目、完整正文、来源和本地归档信息；
- 已制成句子卡的原句保持荧光标记，并注明 structure、vocabulary 或 mixed sentence；
- 点击句子主体进入对应句子卡；
- Core 在正文中加粗，悬停后提示且可点击进入学习；Appreciation 使用较轻的暖色点状下划线，悬停、键盘聚焦或点按只显示简短释义；
- 从搜索结果、句子卡或 Collocation 返回原文时，会自动定位并短暂闪烁目标句子。

## 7. 学习记录与进度

系统使用本地 SQLite 保存：

- 句子 Recall / Use 尝试；
- Collocation Learn / Recall / Use 尝试；
- 自评、是否查看答案、作答耗时和完成时间；
- 学习阶段、成功次数、到期时间；
- 句子收藏、置顶等本地状态的数据库预留字段。

进度页目前主要展示句子覆盖、学习阶段、最近七天活动、训练类型、主题覆盖和最近练习句子。Collocation 已有独立进度与筛选数据，但尚未在总进度页形成完整的综合统计面板。

## 8. 内容生产与可信度控制

正式内容遵循固定工作流：

```text
raw source
→ 来源 metadata、访问日期与内容 hash
→ Codex 离线提取
→ Schema、确定性规则和重复检测
→ candidate
→ 人工审核或修改
→ approved seed
→ SQLite
```

关键原则：

- Codex 生成内容只能先进入候选态；
- 未经人工批准的句子、Collocation 或应用题不能进入正式学习；
- 每条正式句子和 Collocation 都能定位回真实原文；
- 不为凑固定数量而收句，也不因超过估算数量而删除好句；
- 应用题校验会拒绝缺少目标表达、重复题目、重复答案、照抄原句或退化为单独词义的内容；
- 内容 revision 更新不会覆盖已有学习进度和尝试记录。

项目保留内部候选审核台，可逐条查看来源、修改内容、记录审核理由并发布。该功能属于内容维护工具，不是普通学习者主流程。

## 9. 当前技术形态

- Next.js 16 + React 19 + TypeScript；
- 本地服务端渲染 Web 应用；
- `better-sqlite3` 本地数据库；
- JSON Schema + 确定性语义校验；
- Vitest 单元测试和数据库集成测试；
- 当前验证基线：18 项 Schema/内容 fixtures、83 个规则单元测试、19 个数据库集成测试、TypeScript 检查、生产构建和 Collocation Use 浏览器路径全部通过；
- 支持通过 `MIMICLOOP_DB_PATH` 使用独立数据库；
- 当前仅在服务端 feature flag 开启时调用 DeepSeek，对 Sentence Use 与 Collocation Use 做受控评价，并由确定性规则选择通过、重试、最小提示或显示参考答案；基础产品仍可完全关闭该能力，模型 verdict 不直接改写学习进度；
- 当前 Guided Writing 也通过独立开关受控运行，但仍没有 Band 评分、账号、云同步或在线协作。

## 10. 当前阶段判断

MimicLoop 已达到“个人可以持续使用并完整跑通核心学习闭环”的第一阶段 MVP：

- 有真实内容，而不是空壳页面；
- 范文、句子和 Collocation 已经相互连通；
- 句子和搭配都不止于收藏或背诵，而是进入 Recall 与 Use；
- 内容来源、审核和更新具备可追踪流程；
- 学习状态可以跨页面和跨日期保存。

现阶段继续无边界增加小功能，边际价值可能已经低于验证学习效果、改善来源质量和准备真实用户体验。产品下一步的主要问题已经从“还有什么页面没做”转为“哪一种投入最能证明它真的帮助用户写得更好”。

## 11. 已知限制与尚未完成事项

1. **IELTS 范文来源单一**：当前 28 篇均来自 Simon；最初设想中的 IELTS 官方高分考生作答和 Cambridge 正版 model/sample answers 尚未进入正式库。12 篇《新概念英语 3》已完成句子与表达加工，但它们只作为非 IELTS 英语课文单列。
2. **学习效果尚未验证**：目前有完整训练逻辑，但还没有对照实验、前后测或真实用户留存数据证明迁移效果。
3. **开放式答案不自动评价**：句子 Use 和 Collocation Use 依靠参考答案与用户自评，没有语法纠错、表达质量评价或近义答案判断。
4. **复习策略简单**：当前统一在下一个上海自然日到期，尚未根据长期表现形成自适应间隔。
5. **进度呈现不完整**：总进度页以句子为主，Collocation 的 Recall、Use 和应用分数尚未形成综合视图。
6. **单用户架构**：没有账号或访客隔离，多人访问同一实例会共享学习进度。
7. **公开体验尚未准备完成**：内部审核页面尚未保护，版权展示范围、独立体验数据库、反馈入口和部署仍需处理。
8. **移动端与无障碍尚未冻结**：主要页面已有响应式适配，但尚未完成全站窄屏、键盘操作和无障碍验收。
9. **收藏、置顶和正式内容管理未完成**：数据库已有部分字段，但普通用户侧的完整新增、编辑、删除、收藏和置顶功能尚未全部接通。

## 12. 建议与 GPT 讨论的下一步策略问题

建议不要先问“还能加什么功能”，而是从以下方向选择下一阶段主目标：

### 方向 A：先验证学习价值

- 找 3～10 名真实 IELTS 学习者完成短周期体验；
- 设计使用前、使用后和延迟一天的迁移测试；
- 观察用户是否能在新题目中主动调用学过的结构和 Collocation；
- 记录卡在哪一步、哪些提示无效、哪些自评失真；
- 根据反馈删减或调整流程，而不是继续堆功能。

### 方向 B：提升内容可信度

- 确定 IELTS 官方与 Cambridge 内容的合法获取、归档和展示方式；
- 加入 candidate response、examiner-written model answer、Band 和 examiner comments 的清晰区分；
- 重新校准 Simon 内容在整个语料库中的角色；
- 检查当前 186 句、286 条 Core 和 115 条 Appreciation 的主题分布、难度和重复度。

### 方向 C：准备同学体验或比赛展示

- 增加匿名体验者进度隔离或只读演示模式；
- 隐藏或保护 `/candidates` 和内部维护 API；
- 使用独立体验数据库；
- 完成手机端、并发、备份恢复和断网预案；
- 部署到具有持久存储的环境，而不是直接使用无持久磁盘的纯静态平台。

### 方向 D：决定第二阶段是否引入 AI

如果未来考虑运行时 AI，优先讨论它是否只负责：

- 判断用户的新句子是否正确使用目标结构或 Collocation；
- 给出一两条简短、可操作的修改建议；
- 接受合理但不同于参考答案的写法；
- 生成与用户弱项匹配的新语境。

同时需要确定成本、延迟、答案一致性、错误反馈、隐私和离线降级方案。AI 不应破坏现有确定性内容与复习流程，也不应一开始扩展成整篇作文自动评分。

## 13. 适合直接交给 GPT 的问题

> MimicLoop 已完成第一阶段本地单用户 MVP，拥有 28 篇 Simon Task 2 范文、12 篇《新概念英语 3》语言丰富度语料、186 张正式句子卡、286 条 Core 与 115 条 Appreciation 表达，以及句子和 Core 的 Recall / Use 训练。当前没有运行时 AI、账号或云同步。下一阶段应该优先选择“验证学习效果”“引入更可靠来源”“准备多人体验与部署”还是“加入有限 AI 反馈”？请基于产品风险、验证成本和比赛展示价值给出优先级、理由、三到六周路线图，以及明确不建议现在做的事项。
